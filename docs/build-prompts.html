LomasAI · Build sequence · 14 prompts

Build Prompts

Run these in order, one at a time. Each produces something you can actually test before you move on, and each names what it must not touch — which is how the isolation rules survive contact with a deadline.

How to use these
  1. Paste one prompt. Let it finish. Run its acceptance check before starting the next.
  2. If the check fails, fix it in that prompt's scope. Do not carry a broken step forward — every later prompt assumes the earlier ones hold.
  3. Commit after each one. Fourteen commits, each a working system.
  4. P0 to P4 need no hardware, no keys, no Pi. Work on the laptop.
Phase A · Foundation — laptop only, no hardware
P0
Skeleton and core
packages/lomas_core · ~9 files · no dependencies

Prompt

Create the LomasAI repository skeleton and the lomas_core package only. Layout: run.py at root; packages/ for capability packages; app/ for the integrator; config/, content/, tests/. Python 3.12, no framework yet. Build lomas_core with exactly these modules, one job each: - registry.py — a generic Registry[T] with a @register(key) decorator and auto-discovery that imports every module in a package directory so implementations self-register on import. - config.py — four-layer loader: config/default.yaml, then config/profiles/{mode}.yaml, then optional site.yaml, then env vars prefixed LOMAS__ and --set key=value pairs. Last layer wins. Dotted access. - schema.py — typed config models (dataclasses or pydantic). This is the ONLY file in the repo where a default value may be written. - events.py — an EventBus with publish, subscribe by event name or wildcard, and a bounded replay buffer. Sync and async subscribers. - contracts.py — event name constants and payload dataclasses. Empty for now apart from session.opened and session.closed. - clock.py — a Clock protocol with a real and a fake implementation, so tests never sleep. - logging.py — logger factory that reads runtime.mode and emits human lines in user mode, structured records in debug mode. - errors.py — the exception hierarchy. Write config/default.yaml with the runtime and tenancy sections only, every key commented with what it does. Also write the three architecture-enforcing tests now, before there is anything to enforce: - test_imports.py — walks the AST of every package; fails if a package imports a sibling package or anything under app/. - test_no_literals.py — flags bare numeric or string literals used in comparisons or as default arguments outside schema.py. - test_config_layers.py — proves each layer overrides the one below. Comments: sparse, only where the reason is not obvious from the code. No docstring on every function, no narration of obvious steps.
Acceptancepytest tests/ passes with three tests green, and python run.py --mode debug --set runtime.log_level=DEBUG prints the resolved config and exits cleanly.

Must not touch: nothing exists yet. Do not create any other package, and do not add FastAPI, OpenCV or any AI library to requirements.

P1
Storage and tenancy
packages/lomas_store · ~14 files

Prompt

Build the lomas_store package. It may import lomas_core and stdlib only. - store.py — Store protocol: execute, query, transaction. - backends/sqlite.py and backends/memory.py, both registered. - schema.sql — orgs, schools, classes, students, consent, embeddings, sessions, session_students, answers, events. Every table carries org_id. There is deliberately no column anywhere for an image or a video. - migrations.py — versioned, forward-only. - scope.py — a TenantScope value object holding org, school, class. - repos/ — one file per aggregate. Every public method takes TenantScope as its first argument and applies it to the query. Not optional, not defaulted. Add the storage and tenancy config sections. Tests: a tenancy isolation test that seeds two orgs with identical class and student names, writes a session in each, and asserts neither org's queries return the other's rows. Plus a test that the repo layer cannot be called without a scope.
AcceptanceTenancy test passes. Deleting the scope argument from any repo method makes the suite fail.

Must not touch: lomas_core. If you need something from core that is missing, stop and say so rather than editing it.

P2
Camera sources and the frame bus
packages/lomas_vision · ~11 files

Prompt

Build lomas_vision. Frames only — this package must know nothing about faces, students or lessons. - frame.py — Frame dataclass: source_id, seq, timestamp, image array. - source.py — CameraSource protocol: open, read, set_zoom, close. - sources/ one file each, all registered: mock.py (synthetic frames), folder.py (still images, deterministic), file.py (video replay), usb.py (OpenCV), picamera2.py (Pi, import guarded so it does not break on a laptop), rtsp.py (stub that raises NotImplemented with a clear message — the CCTV seam). - bus.py — FrameBus reading from N sources concurrently into a per-source ring buffer, drop-oldest, with a subscribe API. - zoom.py — maps a 1.0–2.5 zoom factor to a centred sensor crop rectangle for picamera2 ScalerCrop; a no-op for other sources. Config: sources is a LIST from day one, each entry with id, kind, zone, resolution, fps, zoom, rotation. Ship one entry. Tests run against mock and folder sources only, no hardware.
AcceptanceA test opens three mock sources at once, pulls 100 frames, and asserts sequence numbers are monotonic per source with no cross-contamination. Nothing imports lomas_face.

Must not touch: lomas_core, lomas_store.

P3
Detection, tracking, pose
packages/lomas_face · ~13 files

Prompt

Build lomas_face. It receives image arrays and returns data. It must never open a camera, and must not import lomas_vision. - types.py — FaceBox, Landmarks, Track, Pose, Identity. - detector.py + detectors/: yunet.py (OpenCV FaceDetectorYN, the default), mediapipe.py, mock.py. - tracker.py — IoU-based track association with birth and death thresholds. Tracks carry a stable id and an optional identity that persists across frames. - pose.py — yaw and pitch from the five landmarks YuNet returns. No extra model. - attention.py — per-track attention score as an EMA over a config window, using the pose cone. Emits a disengagement signal after min_duration below threshold, respecting a per-student cooldown. Config: the face and attention sections. Every threshold, window, cone angle and cooldown is a key. No numbers in the code. Tests use the mock detector and a scripted sequence of boxes so tracking and attention logic are tested without any model or image.
AcceptanceTracker test: a face moving across scripted frames keeps one track id; two faces crossing do not swap ids. Attention test: a scripted head-turn sequence triggers disengagement exactly once, then respects cooldown.

Must not touch: any other package. Detection accuracy is not the goal here — the state machine around it is.

P4
Enrolment and recognition
lomas_face embedder + identity · ~6 files

Prompt

Add recognition to lomas_face. - embedder.py + embedders/arcface_onnx.py (onnxruntime, 112x112 input) and embedders/mock.py (deterministic vectors for tests). - identity.py — matches an embedding against a set of enrolled vectors using cosine distance and a config threshold. Implements the recognise-once-then-track policy: identify only on NEW tracks, and re-verify an existing track every reverify_seconds. - enrolment.py — takes a sequence of frames from a head-turn sweep, scores each for blur and angle, keeps the best N, returns an averaged vector plus the variant vectors. It returns vectors and nothing else — it must not write, cache or return any image. Wire the embeddings repo from lomas_store through the app later, not here. Config: match_threshold, reverify_seconds, enrolment sample count, quality floors, privacy.recognition_enabled, privacy.require_consent. Test with the mock embedder: enrol three synthetic identities, assert correct matching, assert an unknown face returns no identity, and assert that recognition runs once per new track rather than per frame.
AcceptanceThe per-frame call count for the embedder in a 100-frame test with one stable track is 1, not 100. That number is the whole design.

Must not touch: lomas_vision, lomas_store.

Phase B · Voice and reasoning
P5
Speech in, speech out, wake word
packages/lomas_speech · ~14 files

Prompt

Build lomas_speech. - wake.py + wakes/: openwakeword.py (default), porcupine.py, keyboard.py (press a key to simulate the wake word — this is what makes the whole flow testable with no microphone). - stt.py + stts/: groq.py, vosk.py, keyboard.py (typed input). - tts.py + ttss/: piper.py (default), gtts.py, null.py. - devices.py — audio input is a LIST of devices, each with a zone id, even though there is one today. This is the per-desk microphone seam. - duplex.py — a gate that mutes inputs while TTS is playing, with a configurable tail delay. Every engine takes a language code. TTS voice is a per-language map in config, not a single voice string. Tests use keyboard and null implementations only. No audio device is touched in the test suite.
AcceptanceWith speech.wake.engine=keyboard, stt.engine=keyboard and tts.engine=null, a test drives a full wake → transcript → speak cycle with no sound hardware present.

Must not touch: any other package.

P6
AI providers and routing
packages/lomas_llm · ~9 files

Prompt

Build lomas_llm. - types.py — Message, Completion, Usage. - provider.py — LLMProvider protocol: complete() and stream(). - providers/: offline.py (rule-based and canned answers, the default so the system runs with zero API keys), groq.py, anthropic.py, openai.py. - router.py — port the complexity scoring from the existing AI_Assistant router. Scores route to exactly one model, never a chain. Every weight and threshold from config. - prompts.py — loads templates from config/prompts/{language}/*.yaml. No prompt text may appear in any .py file. Config: provider, model, fallback_provider, temperature, max_tokens, timeout, retries, stream, and the router thresholds. Tests use the offline provider. One test asserts that swapping llm.provider changes the class the container builds, with no other change.
AcceptanceFull test suite passes with no API key set anywhere in the environment.

Must not touch: any other package. Do not put prompt strings in code — the multilingual requirement dies the moment you do.

Phase C · The product
P7
Container, flow engine, the six steps
app/ · the first integrator · ~13 files

Prompt

Build the app/ integrator layer — the first code allowed to know all the packages exist. - container.py — reads config, resolves every registry key, constructs and injects. The only file in the repo where concrete class names appear. - flow/states.py, flow/machine.py — the transition engine. - flow/steps/ — attendance, greeting, lesson, interaction, quiz, wrapup. Each a FlowStep with enter, tick, exit. Each in its own file, each registered, the running order read from flow.sequence in config. - orchestrator.py — owns a session: opens it, drives the machine, publishes events, closes it. Handles pause, resume and safety halt as interrupts from any state. Steps communicate ONLY by publishing events. A step may not call another step or reach into the orchestrator. Greeting addresses the class as a whole and does not name individuals. Names are used only when a step or agent addresses one student directly. Content: content/{language}/{grade}/{subject}/ with lessons and quizzes as JSON. Write two real lessons and one quiz for Grade 6 science in English as the reference pack. Acceptance target: python run.py --mode debug walks a complete session headless with mock speech and the offline provider, printing every state transition, and writes the session to SQLite.
AcceptanceA full class runs end to end in under a second with the fake clock. Removing any single step from flow.sequence still produces a valid session.

Must not touch: the packages. If a package is missing something, note it and stop — do not reach in and edit.

P8
The vision pipeline
app/pipeline.py · wires vision to face · ~3 files

Prompt

Write app/pipeline.py, the integrator that joins lomas_vision to lomas_face. This is the only place those two packages meet. Flow: FrameBus → downscale to the configured detection size → detect at detect_fps (not capture fps) → track → identify new tracks only, cropping from the FULL resolution frame not the downscale → pose → attention. Publishes: vision.tracks, student.identified, student.left, student.disengaged. Nothing else in the system may read frames directly. Run it in its own thread with a drop-oldest queue so vision can never stall the session. If the queue backs up, log it in debug mode and drop. Test the whole pipeline against a recorded video through the file camera source, asserting a stable identity across the clip.
AcceptanceRecord a 30-second clip of two people. The pipeline holds both identities for the clip, and the embedder call count is in single digits.

Must not touch: lomas_vision or lomas_face internals. All wiring lives here.

P9
Agents and the MCP context seam
app/agents, app/context · ~9 files

Prompt

Build the agents and the context layer. - context/assembler.py — builds exactly what an agent may see: session state, the current lesson slice, and a student profile. Tenant scope is applied HERE and nowhere else, so an agent cannot read another school. - context/mcp_server.py — exposes that context as MCP resources. - agents/base.py — Agent protocol: handle(event, context). - agents/: tutor (answers student questions at the configured grade level, declines off-syllabus), quizmaster (generates and scores), narrator (storytelling), engagement (subscribes to student.disengaged and produces a nudge), safety (content filter on everything spoken). The engagement agent phrases every nudge as a question, never as a correction. It must never use words like distracted or attention. Put the phrasings in the prompt templates, per language, so they are tunable without code. Each agent has its own model and prompt in config, so the safety filter can run on a cheap model while the tutor runs on a good one. Agents subscribe to events. No step calls an agent directly.
AcceptanceDisabling any agent in agents.enabled leaves a full session running. A test asserts the context assembler refuses a cross-org read.

Must not touch: flow steps. If a step needs to trigger an agent, it publishes an event.

P10
The robot face and the board
app/web · two of the four surfaces · ~10 files

Prompt

Build the web layer and the first two surfaces. - server.py — FastAPI. stream.py — MJPEG endpoint from the frame bus. ws.py — the event stream to browsers. api.py — REST for the teacher controls. ui/face/ — the robot's 7-inch screen, 1024x600, five states: sleeping, listening, thinking, speaking, asking. An animated face: eyes that blink and orient toward the active speaker, a mouth driven by TTS output amplitude. Body text starts at 32px. A persistent student ribbon along the bottom showing name plus a green/amber/grey dot — never a number, never a ranking. ui/board/ — the projector surface for lesson content, enabled by display.board_screen.enabled and served on the second HDMI output. Face boxes are absolutely positioned HTML over the video element, drawn from the vision.tracks event. Never re-encode frames in Python to draw overlays. No frontend framework. Vanilla JS, CSS transitions only, no canvas redraw loop — this runs in Chromium on a Pi 4 and that browser is already your largest CPU consumer.
AcceptanceOn the Pi, the face UI holds 25+ fps of video with boxes tracking correctly, and Chromium stays under about 1.4 cores.

Must not touch: orchestrator or steps. The UI is a subscriber, and only a subscriber.

P11
Enrolment and teacher control
app/web/ui/teacher · ~8 files

Prompt

Build the teacher and admin surface. Enrolment screen — live camera, name and roll number, a consent checkbox that is REQUIRED and writes a consent row, a 3–4 second head-turn capture with a progress ring and live quality feedback, then confirm. It shows how many vectors were stored. It never displays or saves a captured image, and the frames are discarded in the same call that embeds them. Live control screen — video with named boxes, the class roster with attention state, pause and resume, skip section, tap-to-attribute which student is speaking, and a prominent switch that disables nudging for the session. Session report — attendance, coverage, the questions students asked, quiz results per student. No engagement scores, no ranking, nothing a parent could read as a judgement of their child. Pause must halt speech mid-sentence and freeze the flow within 300ms. That button is the teacher's trust in the product; treat its latency as a hard requirement.
AcceptanceEnrol five people, run a lesson, pause and resume it, and read a report that matches what happened. Enrolment without consent is refused by the server, not just the UI.

Must not touch: the face UI.

Phase D · Hardening and hardware
P12
Debug mode and diagnostics
app/web/ui/debug + observability · ~5 files

Prompt

Build debug mode as an overlay available on any surface, toggled by runtime.mode. Shows: capture and detect fps, queue depth and drops, detection count, recognition latency and call count, track table with ids and identities, attention scores, wake word confidence, STT and TTS latency, LLM prompt, token counts and cost estimate, CPU load and SoC temperature, and the last serial frames once hardware exists. Debug mode also: writes sessions to the scratch tenant so bench testing never pollutes a real school's data, raises on error instead of recovering, and logs structured JSONL alongside the console. User mode must show none of this and must recover from errors rather than raise. Confirm both by test.
AcceptanceSame binary, same flow, two modes. A test boots both and asserts the event sink sets and the target tenant differ.

Must not touch: feature logic. Diagnostics are subscribers.

P13
Hardware layer and ESP32 protocol
packages/lomas_hal + firmware · ~8 files

Prompt

Build lomas_hal against the actual BOM: servos on a PCA9685 (2x OT5325M shoulders, 4x MG996R neck and elbows), 2x Rhino encoder DC motors on BTS7960B for drive, ESP32-S3 as the motor controller, HC-SR04 x6, VL53L0X x4 cliff, MPU6050, limit switches, e-stop, ACS712. Note this differs from the older spec document, which describes stepper motors. The BOM is correct; the spec is stale. - protocol.py — the wire format, framing, command set, telemetry and error codes. This file is the shared contract with the firmware. - backends/simulator.py — the default. Accepts every command, simulates travel time, emits plausible sensor readings, and logs the exact bytes it would have sent. - backends/esp32.py — pyserial against the same protocol. - gestures.py — namaste, wave, nod played from keyframes in config/hardware/gestures.yaml. No angle in code. The Pi sends intent; the ESP32 owns real-time motion and the safety reflexes. A Python pause must never become a servo glitch. Also write the firmware stub in firmware/esp32/ implementing the same protocol so the embedded intern has a fixed target.
AcceptanceA full lesson runs on the simulator with gesture frames logged. Swapping to esp32 requires only the config change.

Must not touch: anything else. Safety cut-outs are verified on the bench before this goes near children.

One rule for every prompt

If a prompt cannot be completed without editing a file outside its scope, that is a signal the architecture is wrong somewhere — stop and say so rather than reaching across. Every such reach is a future breakage, and they are far cheaper to catch at the moment they are proposed.

Fourteen prompts, four phases. P0–P6 need no hardware and no API keys. P7 is the first moment you can watch a full class run. P10 is the first moment it looks like a product. Companion documents: the school journey and the system architecture.
